# План переноса оригинальной игры на Storm Engine

Цель — папка `pdm-game/`, в которой оригинальные «Корсары» (PDM 1.061) запускаются на открытом движке: те же корабли, острова, города, персонажи, диалоги и сюжет.

## Что значит «перенести скрипты»

В оригинале нет скриптового языка: вся логика — C++ в 104 DLL (`CORE.dll`, `SHIP.dll`, `MAP.dll` …). Скопировать её нельзя. Переносим так:

- **Данные** — модели, текстуры, звуки, таблицы `.idf`, персонажи `.mtx`, корабли `.shp`, действия `.a`, квесты `.ql`, диалоги `.d`. Их конвертируют `tools/pdm2storm.py` и `tools/pdm_ship.py` из купленной копии при запуске. В git они не попадают.
- **Таблицы и карточки** становятся скриптами: `tools/pdm_data2c.py` пишет `program/data/*.c` с атрибутами объектов.
- **Логика** пишется заново на скриптах Storm (`pdm-game/program/*.c`). Это интерпретатор тех же данных, а поведение повторяет DLL оригинала по выводам из декомпиляции. Код Akella в репозиторий не кладём.

## Этапы

Каждый этап заканчивается одинаково:
- запуск без ошибок (`error.log` пуст);
- проверка без нажатий, через autotest на `PostEvent`;
- заметки в `docs/`, видео в `pdm-game/media/`; команды проверки — в [test-commands.md](test-commands.md);
- коммит и push.

| # | Этап | Что делаем | Критерий готовности |
|---|---|---|---|
| П1 | Каркас и данные | `pdm-game/run.sh` конвертирует RESOURCE и все корабли. `pdm_data2c.py` превращает JSON в скрипты, `main.c` загружает мир оригинала | в `compile.log` сводка: типы кораблей, острова, нации, товары, персонажи; на море корабль игрока (Nicolas Sharp) |
| П2 | Все корабли | все 23 корпуса из `Ships.idf`; ванты у кораблей с другим именем такелажа; флаги и гербы на парусах по нации (`nations.idf`); мачты отдельными узлами | смотр флота: каждый тип на воде, видео |
| П3 | Главное меню | `INI/menu.ini` → XINTERFACE: фон `menu-fon-russian.tga`, кнопки `mbutton`, тексты из `TEXTS/RUSSIAN/INI/interface.ini`, курсор, музыка `Menu.mp3`; шрифты `seawolf`/`log-russ` в установке нет — свободная замена с кириллицей | меню как в оригинале: «Новая игра» выводит в море, «Выход» закрывает игру |
| П4 | Море и бой | характеристики из `Ships.idf` (скорость, поворот, прочность, пушки); ядра, урон, тонущий корабль; ИИ противника | бой с кораблём из `.shp` до потопления |
| П5 | Острова и мир | модели островов и фортов из `.def`; карта мира по `islands_x.idf`; переходы море ↔ карта ↔ берег | доплыть от Granda Avilia до соседнего острова |
| П6 | Города и персонажи | `.loc`, модели городов и интерьеров (таверна, магазин, верфь, резиденция); персонажи `.mtx` со своими моделями; формат анимации `.ani` | пройти по улице Granda Avilia, зайти в таверну, NPC на местах |
| П7 | Диалоги | `.d` → интерфейс диалога; условия ссылок; назначение диалогов командами `SET_FOR Person … Dialog` | разговор с NPC по дереву оригинала |
| П8 | Сюжет | интерпретатор `.a` (2433 команды), квесты `.ql`, проверки OBTAIN / KILL / ESCORT / MATCH, `story_lines` | первые квесты выполняются и меняют мир |
| П9 | Интерфейс и экономика | остальные экраны `menu.ini` (настройки, загрузка, сохранение), вступление (`introduction.idf`), торговля (`Goods`, `Towns`), найм (`Crew`, `Officer`), сохранения | купить и продать товар, сохраниться и загрузиться |
| П10 | Прохождение | новая игра от вступления до первой сюжетной развилки | видео прохождения без ошибок |

## Подводные камни

- В скрипте Storm нет экранирования в строках: `"` в данных оригинала генератор меняет на `'`, а `\` остаётся как есть (`"ships\"` — корректная строка).
- Имя атрибута в `obj.(…)` должно быть переменной: `PdmShips.(PlayerCard.ship_key)` не компилируется («missing ')'»), нужно сначала `string key = PlayerCard.ship_key;`.
- В скрипте нет функции перевода в нижний регистр, поэтому ссылки (тип корабля по `.shp`, корабль персонажа) разрешает генератор: поля `type_key` и `ship_key`.
- `speedrate` фрегата VFrigat записан с десятичной запятой (`10,8`), генератор меняет её на точку.
- Флаг строится из меток `f1`/`f4` (верх и низ у мачты) и `f2`/`f3` (верх и низ свободного края). Без метки `f4` движок считает флаг вымпелом и рисует его вырожденным.
- Герб паруса задаётся по имени узла (`<узел>.Gerald` в `GetSailTextureData`), поэтому парус sub 6 выносится в свой узел `rey_emblem<N>`.
- Узел без мешей ломает запись `.gm`: парус без своих мешей рея остаётся в узле мачты.
- Имена корпусов для `pdm_ship.py` — в нижнем регистре: иначе появляются папки `models/ships/Pink` рядом с `pink`.
- `object` — ключевое слово скрипта: поле условия квеста называется `kind`.
- Динамический вызов: `string f = …; call f();` — имя функции должно лежать в локальной строковой переменной.
- Без секции `[PC_SCREEN]` в `interfaces.ini` XINTERFACE ничего не рисует: прямоугольник экрана перевёрнут. Нужно `bDynamicScaling = 1`.
- Old Standard шире шрифта оригинала: высота строки уменьшена на 15 % (`FONT_FIT`), иначе «Продолжить игру» не влезает в кнопку.
- `demos/ship/make_ship.py` переписывает `ini/rigging.ini`, поэтому `run.sh` после него дописывает `rigging_pdm.ini`.
- `type` — зарезервированное слово скрипта, параметр `int type` даёт ошибку компиляции.
- Файлы действий персонажей `WORLDS/CHARACTERS/*.idf` записаны в разном регистре (`Traktir_Man.idf`), искать их нужно без учёта регистра.
- Сюжет пишет остров персонажа не так, как ключ острова (`Gray Sails` / `Gray_Sails`, `d'Orange` / `d_Orange`): сравнивать после нормализации.
- Патчи оригинала перекрываются, а движок ходит только через общие рёбра: без вычитания перекрытий улица распадается на десятки несвязанных кусков.
- `NPCharacter` с задачей `Goto point` останавливается примерно в 0,2 м от цели: цель автотеста ставится на полметра внутрь двери.
