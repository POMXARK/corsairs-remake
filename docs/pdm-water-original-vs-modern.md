# Вода и корабли: оригинал и ремастер

Сводка по разбору `sea.dll`, `CinemaSun.dll`, `SUN.dll` оригинала и по нашему движку (`pdm-game/program/sea.c`, `cutscene.c`). Подробности и адреса — в [pdm-cutscenes.md](pdm-cutscenes.md).

| | Оригинал | Ремастер (Storm Engine) |
|---|---|---|
| Волны | Процедурно: `GetHeight(x, z)` — сумма трёх октав по таблице синуса из 1024 значений, нормированная на пик `125 · amplitude` (`sea.dll`, slot 20). | Две карты высот: 64 кадра `make_sea.py` (`Sea.Sea2.Amp1`/`Amp2`, `Scale`, `AnimSpeed`), высота = кадр · амплитуда. |
| Амплитуда | `sea_amplitude` 0,00006 (штиль) – 0,0011 (шторм) ⇒ пик 0,0075–0,14 единицы. | `Amp1 = 3,0`, `Amp2 = 0,8` (метры): на порядки выше, поэтому в роликах задаём `Amp1 = sea_amplitude · 125`. |
| Уровень моря | Поле объекта моря (`+0x144`), задаётся вызовом slot 19 снаружи (остров/модель); в записи ролика нет. | Плоскость `y = 0`; модели и камеру ролика поднимаем на `LIFT` (1,5; ночью 2,5), подобрано по кадрам. |
| Параметры воды | Скорость, амплитуда, тайл, прозрачность (≈ 624–724), частота (50–200) приходят сообщением `0xe`; скорость, амплитуда и прозрачность дублируются в слотах 6–8 объекта `coordinator`. | `Sea.Sea2.*`: `Transparency`, `Frenel`, `Reflection`, `Attenuation`, `BumpScale`, `FoamEnable` и др. |
| Вид | Фиксированный конвейер DirectX (2000 г.): сетка, текстура `sea_*.tf`, цвет по прозрачности и туману; шейдеров нет. | Шейдеры: отражение неба (`SEA_REFLECTION`), Френель, пена, LOD-сетка. |
| Небо | Текстуры `sky_*.tf`, `sun_*.tf`, `moon_*.tf` (закрыты). | Три свободных пресета (`day`, `storm`, `sunset`), `overcast` и ночь — перекраской. |
| Погода | 19 периодов `weather.ini` по часам; в ролике — один период в записи `0x1a`. | Атрибуты `Weather.*`, `Sea.Fog.*`; в роликах значения берутся из записи. |
| Корабли в ролике | Обычные модели `.cff`/`_a.cff` с ключами положения; плавучести нет, вода только фон. | Skinned-модель сцены `cinema_<сцена>.gm` с ключами; плавучести тоже нет: корпус «стоит» на `LIFT`. |
| Корабли в игре | Модуль корабля оригинала не разбирался. | Сущность движка `ship` (парус, пушки); связь корпуса с высотой волн в `pdm-game` не проверялась. |

## Известные различия, видимые в роликах

- В игре волна в сотни раз выше оригинальной: без замены амплитуды камера уходила под воду, а волны закрывали корабли.
- Горизонт и «ватерлиния»: оригинальный уровень воды неизвестен, поэтому корабли ставятся по кадрам (сейчас полкорпуса в воде при `LIFT = 1,5`).
- Прозрачность воды и пена выглядят иначе: у оригинала нет Френеля и пены.

## Корабли и волны движка

- Ключи кораблей почти не меняют Y (≤0,06 ед.): киль стоит на ватерлинии ролика y = 0. Общий `LIFT` относится только к камере.
- Движок: сообщение `MSG_SEA_GET_HEIGHT` (50202, `"lff"`, x, z) пишет высоту волны и наклон в `Sea.Probe.{Y,NX,NZ}`.
- `cutscene.c` (`Cut_Ride`) каждый кадр ставит модели на `высота волны + CUT_DRAFT` (−0,3: корпус чуть в воде). Крен по нормали пока не применяется.

### Уровень посадки по роликам

Уровень корпусов над волной движка задаётся в `tools/pdm_cutscene.py`: `DRAFT` — общий (0.0 = киль на волне), `DRAFTS = {"scene10": -0.3}` — для отдельных роликов (ключ — имя сцены в нижнем регистре; плюс — выше, минус — глубже). Значение попадает в `<сцена>.draft` данных и читается в `Cut_Load` (`cutDraft`). После правки — перегенерировать `python3 -I tools/pdm_cutscene.py <Корсары> pdm-game`.
