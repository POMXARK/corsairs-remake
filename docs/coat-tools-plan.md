# План: инструменты 3DCoat без 3DCoat

Цель — иметь открытые копии инструментов 3DCoat, которые нужны для правки моделей, и применять их к любой модели на Linux. Что уже сделано и как измерено — в `docs/coat-tools.md`.

Как работаем: 3DCoat изучаем как чёрный ящик — подаём сетки через Python API и смотрим результат. Дизассемблировать нельзя по EULA, п. 4.1. Ghidra остаётся только для оригинальной игры.

Цикл каждого пункта:
1. Тестовые сетки — `coat_probe.py make`.
2. Прогон в 3DCoat — `coat_probe.py run`. 3DCoat запускается свёрнутым, `MIN=1`.
3. Сравнение с открытым алгоритмом — `coat_probe.py analyze`.
4. Копия в `coat_algos.py` и её проверка — `verify`.
5. Запись в `docs/coat-tools.md`, коммит.

## Дальше, по порядку

### 1. Свёрнутый запуск для UV-режимов
**Статус: сделано.** Прогон probe2 (48 задач, 179 с) свёрнутым; Auto Seams на голове дал те же 230 островов.
- **Зачем:** UV-режимы (`auto`, `export`) переключают комнаты и закрывают диалоги, и свёрнутое окно может это сорвать.
- **Шаги:** прогнать `coat_run.sh fix2/solid.obj out.obj auto` с `MIN=1`, сравнить с прежним `solid_auv.obj`: число островов и uv_score.
- **Готово, когда:** результат тот же. Если зависает — в `coat_run.sh` для UV-режимов ставить `MIN=0`.

### 2. Правило Auto Seams
**Статус: частично.** Измерено: конус нормалей острова до 45–60°, острые рёбра режутся всегда. Приближение `coat_algos.charts` (VSA) совпадает на призмах, кубе и сфере; на голове (607 островов против 230) и торе (6 против 2) — нет.
- **Зачем:** разрезы без 3DCoat на любой модели и без осколков.
- **Сетки:**
  - куб с фасками 10°, 20°, 30°, 45°, 60° — порог угла;
  - цилиндр и тор — где режет замкнутые трубки;
  - шумная сфера — откуда берутся осколки;
  - сетка головы на 5 и 20 тыс. граней — зависит ли от плотности.
- **Нужно:** добавить в `coat_autouv.probe` операцию `autoseams`: импорт, `$AutoEdges`, запись разрезов через `coat.uv.getSeams`.
- **Готово, когда:** найдены порог угла и правило для осколков; `coat_algos.autoseams` повторяет разрезы 3DCoat (доля совпадающих рёбер > 90 %).

### 3. ABF (метод 2)
**Статус: сделано**, `coat_algos.abf` (Ньютон по углам, затем LSCM по углам).
- **Зачем:** развёртка с углами как у LSCM, но с меньшим растяжением площади.
- **Шаги:** сравнить выход 3DCoat с ABF++ (Sheffer и др., 2005) по статье. Взять готовую свободную реализацию, если найдётся (лицензия MIT/BSD), иначе написать на scipy.
- **Готово, когда:** остаток < 0,02 на тестовых сетках.

### 4. Упаковка `uv.pack`
**Статус: сделано.** Режим `pack` есть в `coat_autouv.probe`. Открытая копия — `coat_algos.pack` (xatlas, полный перебор, отступ 2 из 2048): 0,673 против 0,670. Режима упаковки через 3DCoat в `uv_unfold.py` пока нет.
- **Зачем:** у нас упаковывает xatlas, и он хуже 3DCoat. На hero1 заполнение 0,60 против 0,69, uv_score 2,4 против 3,97.
- **Шаги:**
  1. Добавить в `coat_autouv` режим `pack`: импорт obj с готовой UV, `coat.uv.pack(0, rotate, shuffle)`, `$ApplyUV`, запись.
  2. Измерить на наборе прямоугольников и на атласе `uv_unfold`: повороты (90° или любые), отступы, порядок по площади, масштаб островов.
- **Готово, когда:**
  - `uv_unfold.py` может упаковать через 3DCoat (свёрнутым);
  - открытая упаковка (`coat_algos.pack` или настройки xatlas) по заполнению не хуже 3DCoat на 0,03.

### 5. Развёртка полос (метод 4)
**Статус: тупик.** На полосах из треугольников 3DCoat отдаёт одни нули.
- **Зачем:** пряди, ремни, канаты — длинные куски без искажения.
- **Шаги:** сетки-полосы (прямая, изогнутая, скрученная) и выход 3DCoat; копия — развёртка вдоль средней линии.
- **Готово, когда:** остаток < 0,02.

### 6. Объёмные инструменты
**Статус: измерено.** Копия есть только для `relaxSurface` (`vrelax`). Для вокселей (`relaxVoxels`, `closeHoles`, ремеш) открытой копии нет.
`Volume.relaxSurface`, `relaxVoxels`, `closeHoles`, `fromVolumeWithMaxPolycount`.
- **Шаги:** шар и куб с дыркой известного размера. Измерить:
  - сдвиг поверхности от степени;
  - какие дыры закрываются, по размеру;
  - число граней и их равномерность после ремеша.
- **Копии:** через открытые библиотеки (voxel → marching cubes в scikit-image, сглаживание, закрытие дыр морфологией).
- **Готово, когда:** открытая копия даёт ту же форму, расстояние Хаусдорфа < 1 % размера.

### 7. `reduceToPolycount` и `weld`
**Статус: сделано**, `coat_algos.reduce` и `coat_algos.weld`.
- **Шаги:** сравнить с quadric decimation (open3d / pymeshlab) по ошибке формы и сохранению краёв UV; `weld` — по расстоянию слияния.
- **Готово, когда:** известно, чем заменять и с какими параметрами.

### 8. Применение к другим моделям
- **Шаги:** прогнать конвейер на второй модели (другая голова или предмет) только открытыми копиями: части → разрезы → развёртка → упаковка → проекция видов. Сравнить с вариантом через 3DCoat по `uv_score` и `head_check`.
- **Готово, когда:**
  - открытый вариант не хуже на 10 %;
  - рецепт записан в `docs/head-model-fix.md` и в скилл `head-model-fix`.

## Самообучающийся исправитель моделей (`head_agent.py`, `head_gui.py`)

Открытые копии нужны прежде всего ему: каждая становится «ходом» агента, а агент сам учится, где какой ход помогает. Он работает без Windows, поэтому может делать сотни проходов.

Сейчас:
- 16 ходов: relax, membrane, push, repaint, hair_to_skin, skin_to_hair, blur;
- награда — прирост оценки области `region_score`;
- политика `head_policy.json` — средние награды по контексту, части и в целом, выбор ходов по UCB;
- опыт: в `fix2/policy.json` всего 3 прогона, 11 ходов, 2 контекста — почти ничего;
- промпт разбирается словарём;
- модель — одна голова, hero1.

### А. Новые ходы из открытых копий
- **Ходы:**
  - `open_relax` с `degree` 0,5 / 1 / 2 и `tangent` 1 — сглаживание без усадки;
  - `open_relax` с `crease` 40 — сохраняет острые края век, губ и ушей;
  - `unfold` области — новая развёртка ARAP/LSCM только граней области с перекраской из видов: светлые пятна на хвосте, растянутые тексели;
  - позже — свои разрезы области по правилу Auto Seams (п. 2 выше).
- **Нужно:**
  - в `head_tools.TOOLS` инструменты `open_relax` (есть) и `region_unfold` (новый);
  - в `head_agent.ARMS` — ходы с параметрами;
  - в априорных весах — намерения: `smooth` → `open_relax`, `skin_off` → `region_unfold`;
  - в `region_score` — растяжение текселей области (`uv_score` по граням области), иначе награда не видит пользы от развёртки.
- **Готово, когда:** агент на глазах и хвосте hero1 сам выбирает новые ходы, а оценка выше, чем со старыми 16 (сравнение по 10 проходов).

### Б. Обучение на многих моделях
- **Зачем:** 3 прогона — это не обучение. Политика должна набирать опыт на разных головах и разных областях.
- **Шаги:**
  1. Добавить `head_train.py models/*.glb`: на каждой модели — части (`head_parts.py`), затем агент по каждой проблемной части. Проблемные части берутся из `head_check`: он выдаёт недочёты с рецептами, и каждый недочёт становится областью и намерением.
  2. Общая политика у всех моделей, прогон в фоне. Отчёт: какие ходы выигрывают для какой части.
  3. Модели: головы из `output/3d` (hero1 разных версий, другие персонажи после генерации).
- **Готово, когда:** на модели, которой не было в обучении, агент с обученной политикой достигает той же оценки за меньшее число проходов, чем с пустой (меньше откатов).

### В. Обучение на ручных правках
- **Зачем:** в окне правки человек выбирает область и инструмент сам — это лучший пример.
- **Сейчас:** ручная правка в `head_gui` уже обновляет веса.
- **Нужно:** сохранять пару «до → правка → после» в `work/manual/`. Ручная правка, которую человек оставил, получает награду выше, даже если оценка упала: значит, оценка ошиблась. Такие случаи — материал для правки весов `region_score`.
- **Готово, когда:** есть журнал ручных правок и отчёт «оценка против человека» (где они расходятся).

### Г. Промпт локальной моделью
- **Зачем:** словарь `INTENT_WORDS` понимает только заготовленные корни слов.
- **Шаги:** локальная LLM (Ollama/llama.cpp, 3–8 млрд параметров, без внешних сервисов) получает промпт, список частей и намерений и отвечает JSON тем же форматом, что `parse_prompt`. При ошибке — откат на словарь.
- **Готово, когда:** на наборе из 30 промптов (с опечатками, как пишет пользователь) части и намерения угаданы ≥ 90 %. Набор и результат — в `docs/head-model-fix.md`.

### Д. Не только головы
- **Зачем:** применять к другим моделям — кораблям, предметам, телам.
- **Шаги:**
  - части — не MediaPipe, а свои метки: по связности, по острым рёбрам (правило Auto Seams), по видам с подписями;
  - `region_score` без «кожи/волос» — только цвет против видов, складки, растяжение UV, уход формы;
  - эталонные развёртки по типам частей (труба, плоскость, полоса — п. 5, коробка).
- **Готово, когда:** агент прогнан на одном предмете (например, бочке или пушке из ассетов) и его оценка выросла без ручной помощи.

### Е. Всё это — в окне правки (`head_gui.py`)

Каждый пункт выше должен быть доступен из окна, а не только из командной строки. Список инструментов окно берёт из `head_tools.TOOLS`, поэтому `open_relax` там уже есть: в ручном применении, с параметрами `degree`, `tangent`, `crease`.

| Что | Где в окне | Зависит от |
|---|---|---|
| новые ходы (`open_relax`, `region_unfold`) с подписью «как в 3DCoat, без Windows» | список инструментов, кнопки с готовыми параметрами (слабо / средне / сильно) | А |
| развёртка области: до и после — сетка UV области поверх текстуры, наложение красным, растяжение цветом | вкладка «UV» | А, п. 3–5 |
| «3DCoat на Windows» — запуск свёрнутым (`coat_run.sh`, `MIN=1`), полоса хода, итог в журнал, сравнение с открытой копией | кнопка рядом с инструментом, только если есть ssh к ПК | п. 1, 4 |
| обучение на папке моделей: выбор папки, число проходов, ход в фоне, «■ стоп» | вкладка «Обучение» | Б |
| что выучено: таблица «часть × ход» (средняя награда, число попыток), график средней награды по прогонам, сброс и выгрузка `head_policy.json` | вкладка «Обучение» | Б |
| ручная правка: «оставить, хотя оценка упала» и короткая причина; журнал ручных правок; случаи, где оценка спорит с человеком | журнал + кнопка у прохода | В |
| разбор промпта: какие части и намерения поняты (словарь или локальная модель), с правкой галочками перед запуском | под полем промпта | Г |
| другая модель: открыть glb/obj без MediaPipe-частей, части по рёбрам и связности, выбор типа модели (голова / предмет) | «Открыть» | Д |

**Как проверять окно:**
- открыть `head_gui.py fix2/afinal.glb …`, пройти каждую новую кнопку;
- снимок окна — Chrome headless или `linux-live-control`;
- журнал без ошибок.

Окно слушает только 127.0.0.1, сторонних библиотек в нём нет: только stdlib Python.

**Готово, когда** весь путь «открыть модель → выделить → промпт → агент → посмотреть UV → сохранить» и обучение на папке делаются только из окна.

Порядок: А → Б → Д, а В и Г — параллельно, когда есть время. Окно (Е) — вместе с каждым пунктом: пункт закрыт, когда он есть и в окне. А зависит от п. 2 (разрезы) только частично: `open_relax` и `region_unfold` можно делать сразу.

## Тупики (не повторять)
- **LSCM на сложенных дырявых островах** не совпадает с 3DCoat. Выбор закреплённых вершин этого не объясняет; прямое решение и lsqr дают один и тот же ответ.
- **ARAP вместо проекции** не убирает наложение у островов, свёрнутых в 3D: нужны разрезы.
- **ARAP в `uv_unfold`** хуже LSCM: uv_score 2,06 против 2,40.
- **3DCoat совсем без окна** (из ssh без рабочего стола) не работает: нужен рабочий стол пользователя, поэтому запуск идёт через задачу `coatrun` с `/it`.
