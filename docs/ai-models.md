# Нейрогенерация 3D-моделей

Как заменить модели оригинала более детальными. Бесплатно, локально на RTX 5080, пачкой через ComfyUI. Модель рисуется с четырёх сторон, нейросеть делает по видам новый меш, конвертер ставит его в игру на место старого и переносит кости.

## Что можно заменить

| Что | Можно | Почему |
|---|---|---|
| Персонажи (скиннинговые `.gm`) | да | скелет и анимации остаются от оригинала, новые вершины цепляются к костям ближайших старых |
| Статичные модели без меток (предметы, бочки, мебель) | да | меш просто подменяется, масштаб и положение подгоняются |
| Корабли, локации | нет | в них есть метки (`locators`): канаты, паруса, пушки, точки входа. Они привязаны к старой геометрии, поэтому конвертер такие модели пропускает |

## Выбор шаблона ComfyUI

Нужны локальный запуск, свободная лицензия и меш на выходе, а не облако точек и не сплаты.

| Шаблон / ноды | Лицензия | Вердикт |
|---|---|---|
| **Pixal3D: Multi Views to 3D** | MIT (код и веса) | **основной**: четыре вида из `pdm_model_views.py`, по ним модель лучше видна со спины |
| **Pixal3D & TRELLIS.2: Image to Model** | MIT (TRELLIS.2, Microsoft) | запасной: один вид спереди, а спину модель додумывает |
| HY 3D 2.1 / 2.0 / 2.0 MV / 2.0 MV Turbo (Hunyuan3D) | Tencent Hunyuan Community License | нет: лицензия не действует в ЕС, Великобритании и Южной Корее, а портфолио публичное |
| TripoSplat: Image to Gaussian Splat | MIT | нет: результат — гауссовы сплаты, Storm Engine рисует только треугольники |
| MoGe: Panorama to Mesh / Perspective Geometry | MIT | не для моделей: глубина и геометрия по фото. Пригодится для фонов и неба |
| SAM 3D Body: Human Mesh From Video | SAM License (Meta) | не для моделей: меш и поза человека по видео. Может пригодиться как референс анимаций |
| Meshy, Rodin, Tripo, Tripo P1/P2, Tencent, Nano Banana 2 | API-ноды | нет: платные, генерация идёт в чужом облаке |

Pixal3D и TRELLIS.2 тянут вспомогательные модели: DINOv3 (DINOv3 License от Meta — бесплатная, разрешает использование и изменение, но лицензия своя, не стандартная) и BiRefNet (MIT, убирает фон). Перед установкой проверьте лицензию на странице каждой модели на Hugging Face: у дообученных версий она бывает другой.

**Права.** Виды рендерятся из моделей и текстур оригинала, поэтому новая модель — производное от данных оригинала. Обращаемся с ней как с остальным сконвертированным: генерируется локально в `pdm-game/data/ai_models/` и `pdm-game/resource/`, в git не идёт (обе папки в `.gitignore`). В git — только скрипты.

Если нужна модель без следов оригинала, вид спереди перерисовывается свободной моделью изображений (FLUX.1 schnell — Apache-2.0) по описанию персонажа и кладётся вместо `<name>_front.png`. Тогда лучше брать шаблон с одним видом.

## Инструменты

| Файл | Что делает |
|---|---|
| `tools/pdm_model_views.py` | рисует `.gm` с текстурами спереди, справа, сзади и слева без перспективы → `data/ai_models/views/<name>_<вид>.png` (шаг 1) |
| `tools/comfy_model_batch.py` | очередь ComfyUI на все виды → `data/ai_models/glb/<name>.glb` (шаг 3) |
| `tools/pdm_glb_optimize.py` | GLB → облегчённый GLB в `data/ai_models/glb_opt/` (шаг 3.5) |
| `tools/pdm_glb2gm.py` | GLB → `.gm` на место оригинала, с костями и текстурой; `--restore` возвращает оригинал (шаг 4) |
| `tools/model3d/image_to_model_api.json` | workflow ComfyUI, экспорт API. Кладётся после сборки графа (шаг 2); данных оригинала в нём нет, его можно коммитить |

## Шаг 1. Виды модели

Из `corsairs-remake`:

```bash
python3 -I tools/pdm_model_views.py pdm-game hero1 characters/girl1 --size 1024
```

Модель ищется в `pdm-game/resource/models` по пути или имени. Фон серый (128), модель занимает 85 % кадра, свет падает спереди сверху. Персонаж рисуется в позе привязки, в той же, где конвертер потом ищет ближайшие кости. Если лицо модели оказалось не на виде `front`, поверните её через `--yaw 90` (180, 270).

## Шаг 2. Workflow

1. Обновите ComfyUI до свежей версии: шаблоны Pixal3D и TRELLIS.2 есть в Template Library. Откройте шаблон «Pixal3D: Multi Views to 3D». Веса шаблон скачает сам.
2. Прогоните его вручную на одном наборе видов и посмотрите результат во встроенном 3D-просмотрщике.
3. Переименуйте узлы (правый клик → Title). Скрипт находит их по названиям:
   - `IMAGE` — Load Image вида спереди;
   - `IMAGE_RIGHT`, `IMAGE_BACK`, `IMAGE_LEFT` — остальные виды; в шаблоне с одним видом их нет;
   - `SEED` — узел с входом `seed` (необязательный);
   - `FACES` — число граней после упрощения (необязательный);
   - `SAVE` — Save 3D (GLB).
4. Включите в настройках Dev mode, выполните Workflow → Export (API) и сохраните в `tools/model3d/image_to_model_api.json`.

Если вход сида или граней называется иначе, задайте его через `--seed-input` / `--faces-input`. Узел с единственным числовым входом получит число и так.

## Всё одной командой

```bash
python tools/pdm_models_all.py pdm-game hero1 officer1 --quality normal          # виды → перерисовка → 3D → облегчение
python tools/pdm_models_all.py pdm-game --steps refine,model,optimize --redo        # заново для всех, у которых уже есть виды
python tools/pdm_models_all.py pdm-game hero1 --install                          # и поставить в игру (--restore в pdm_glb2gm.py вернёт оригинал)
```

Каждый шаг пропускает то, что уже сделано, `--redo` берёт следующий сид. Перерисовка видов требует `tools/model3d/refine_api.json` (`pdm_comfy_refine_graph.py`).

## Водонепроницаемый меш (PixelArtistry)

Почему наш результат хуже, чем в видео https://www.youtube.com/watch?v=dmDrktqyT5o: в шаблоне Comfy-Org сетка получается через `RemeshMesh` (768, solid fill) и сглаживание — детали стираются, руки склеиваются с плащом. Автор берёт ту же модель, но после неё ставит ноды MostAadTech: Quad Reconstruct → **WTiVo** (watertight, разрешение 1536 и 12 млн proxy points; на 16 ГБ — 2048 и 25 млн) → **LODTailor** (облегчение, остаётся watertight) → Fast Merge. Плюс: фон убирает BiRefNet, поле зрения Pixal3D берёт MoGe (а не фиксированные 20°), 20–24 шага вместо 12, текстура 4096, низкополигональная версия печётся через Bake Forger.

Подводный камень: WTiVo поставляется только как `cppmodules.cp312-win_amd64.pyd`, то есть нужен **Python 3.12** (и torch 2.8.0 + CUDA 12.8). В Comfy Desktop (venv на Python 3.13) нода не импортируется (`No module named wtivo_core / cppmodules`), `tools/pdm_install_watertight_nodes.ps1` там не поможет. Нужен отдельный ComfyUI Easy-Install; модели из Comfy Desktop подключаются через `extra_model_paths.yaml`.

Установка (Windows): ComfyUI Easy-Install + ComfyUI-Trellis2 (VisualBruno) и ноды из README https://github.com/pixelartistry/PixelArtistry-Watertight-Meshes (проще всего его `watertightMeshes_win_installer.bat`: прочитайте файл перед запуском). Нужен чистый Blender без аддонов.

Полный журнал установки на Windows и подводные камни: [ai-models-watertight-setup.md](ai-models-watertight-setup.md).

Подключение к нашему конвейеру (ComfyUI запущен):

```
python tools\pdm_comfy_api.py PixelArtistry_01b_Image_to_Watertight_Mesh_2K.json --save 331 --blender "C:\Blender\blender.exe" --out tools\model3d\watertight_api.json
python tools\pdm_models_all.py pdm-game hero1 --steps model,optimize --crop 0.05 --workflow tools\model3d\watertight_api.json --redo
```

`--save`: 331 для 01 и 01b, 343 для 02 (с запечённым low-poly), 341 для 03. Имена параметров кастомных нод конвертер берёт из `/object_info`. 01b — на 16 ГБ, перед запуском закрыть другие программы. Если в сетке дырки — запустить ещё раз (seed структуры случайный). Работы 03 (своя сетка → текстура Trellis 2) подойдут для старых персонажей: Pixal3D текстуру не красит (чёрная).

Авторство: PixelArtistry (MIT), MostAadTech (WTiVo, LODTailor, Quad Reconstruct), VisualBruno (ComfyUI-Trellis2), Comfy-Org (шаблон, MIT), Tencent ARC (Pixal3D), Microsoft (TRELLIS.2).

## Шаг 3. Пакетная генерация

```bash
python3 -I tools/comfy_model_batch.py pdm-game --only hero1          # проба на одной модели
python3 -I tools/comfy_model_batch.py pdm-game --faces 20000         # все виды без готового GLB
python3 -I tools/comfy_model_batch.py pdm-game --redo hero1          # не понравилось — следующий сид
```

ComfyUI может работать на другой машине (`--listen`, адрес задаётся через `--comfy http://host:8188`). Виды загружаются в `input/pdm_models`, файл забирается через `/view`. Готовые GLB пропускаются, поэтому прогон можно прервать и продолжить. Сиды записываются в `data/ai_models/glb/seeds.json`, и повторный прогон даёт тот же результат.

## Шаг 3.5. Облегчить меш

Меш нейросети плотный (50–500 тыс. треугольников), а UV разбросаны по мелким островам. `pdm_glb_optimize.py` режет его до игрового, сохраняя текстуру:

```bash
pip3 install --user trimesh rtree fast-simplification    # один раз; запускать без -I, иначе пакеты из --user не видны
python3 tools/pdm_glb_optimize.py pdm-game hero1 --faces 12000 --tex 1024
python3 -I tools/pdm_glb2gm.py pdm-game hero1 --glb pdm-game/data/ai_models/glb_opt --tex 1024
# hero1[0]: faces 81920 -> 3000, vertices 41532 -> 1502, surface off by 0.04 % (max 0.34 %) of the diagonal, colour off by 1.2/255, texture 1024x1024
```

Что делает:
- сваривает вершины по положению, выбрасывает вырожденные треугольники;
- режет меш квадриками (`fast_simplification`) до `--faces`;
- переносит UV с оригинала: каждый новый треугольник берёт остров оригинального треугольника под своим центром, углы ставятся на этот остров. Так шов не размазывает текстуру по модели, чего не избежать при простом Decimate в Blender;
- сваривает вершины с одним положением и UV, уменьшает текстуру до `--tex`;
- печатает отчёт: насколько новая поверхность ушла от старой (в процентах диагонали) и среднее изменение цвета текстуры. Больше 1–2 % диагонали или 10 уровней цвета — смотреть виды `pdm_model_views.py` или поднять `--faces`.

Результат лежит в `data/ai_models/glb_opt/<name>.glb`, исходный GLB не меняется. Проверено на сфере из 82 тыс. треугольников с разрезом UV по шву и гладкой текстурой: 3000 граней, цвет 1,2/255, поверхность 0,04 %. Мелкий узор в несколько пикселей (шахматка) даёт заметно больший сдвиг цвета: его выровнять упрощением нельзя, только текстурой. На настоящем результате Pixal3D инструмент не пробовался.

Не умеет: ретопологию в четырёхугольники, перепёк текстуры с высокополигональной модели, отдельные LOD. Для персонажей с крупными сгибами проверьте деформацию в игре (шаг 5).

## Шаг 4. Поставить в игру

```bash
python3 -I tools/pdm_glb2gm.py pdm-game hero1 --tex 1024
# hero1: 1828 faces, turned 90, scaled 2.000, off by 0.0 cm, 17 bones
```

Что делает конвертер:
- переводит оси: glTF правосторонний и смотрит в +z, а персонаж движка смотрит в −z, поэтому z инвертируется;
- подгоняет высоту под оригинал, ставит низ на его низ и центр на его центр;
- из четырёх поворотов выбирает самый близкий к оригиналу. Число `off by` — среднее расстояние между моделями в сантиметрах: если оно больше 10–20, модель вышла кривой;
- каждой вершине даёт кость ближайшей вершины оригинала;
- текстуру пишет в `textures/<папка оригинала>/ai_<name>.tga.tx`.

Оригинал один раз сохраняется в `data/ai_models/orig/` и служит эталоном каждого прогона, так что повторный запуск даёт тот же файл. Вернуть оригинал: `--restore`.

## Шаг 5. Проверка

1. Виды результата: `pdm_model_views.py` той же модели в другую папку (`--out`), сравнить с видами оригинала.
2. В игре: `SCENE=town` (герой — `hero1`), анимации ходьбы и разговора, `error.log` пуст.
3. Если руки или полы одежды тянутся не за той костью, модель стоит перегенерировать с другим сидом (`--redo`) или поправить позу на видах.

## Ограничения

- **Одна кость на вершину.** Как в оригинале: на сгибах (локти, колени) новый меш ломается так же, как старый. Чем плотнее меш, тем заметнее; 10–20 тыс. граней — разумный предел.
- **65 536 вершин** на модель (индексы 16-битные). Сверх лимита конвертер останавливается: уменьшите `--faces`.
- **Однослойная текстура.** Берётся только base color; карты нормалей и шероховатости движок оригинала не использует.
- **Вид сзади.** Шаблон с одним видом додумывает спину сам, отсюда «Multi Views» как основной вариант.
- **Мелкие детали** (оружие в руке, шляпа отдельным объектом) сливаются с телом в один меш и двигаются с ближайшей костью.


## Персонаж по частям (`--parts`)

`hero1.gm` — 17 объектов, у каждого своя кость: голова (8, 9), торс (0, 10), руки (1–3 и 5–7), сабля (11), ноги (12–17). Одна сплошная сетка из всего персонажа слипает руки с торсом и саблей, а кость вершине берётся у ближайшей вершины оригинала. Режим `--parts` делает каждую группу отдельной моделью:

```powershell
python tools\pdm_models_all.py pdm-game hero1 --parts --steps views,model --workflow tools\model3d\gameready_api.json --crop 0.05
python tools\pdm_models_all.py pdm-game hero1 --parts --steps optimize,views --install
```

- `pdm_model_views.py --parts` рисует `hero1_<часть>_{front,right,back,left}.png` (группы — `PARTS`, раскладка костей hero1);
- `pdm_glb2gm.py --parts` берёт `hero1_<часть>.glb`, подгоняет к своей части оригинала и вешает только на кости этой части. Проверка на самом себе: сдвиг 0,0 см, 17 костей.
- Скелет другого персонажа с иной раскладкой костей отвергается явной ошибкой.

## Автопроверка моделей (`pdm_model_check.py`)

Как `pdm_voice_check.py` для озвучки: каждая `data/ai_models/glb/<имя>.glb` рисуется с четырёх сторон (облако точек поверхности с цветом текстуры) и сравнивается с видами, из которых сделана. Модель можно повернуть на четверть оборота, берётся лучший поворот.
- форма — пересечение силуэтов (IoU), худшая из четырёх сторон; порог `--iou 0.75`. Выросшее лишнее тело, потерянная кисть, слипшийся рукав роняют его (проверка: оригинал hero1 — 0,93, чужая форма — 0,50);
- цвет — разница среднего цвета модели и вида; порог `--colour 0.18`. Чёрный рукав, ставший красным или коричневым, его повышает.

Результат: `data/ai_models/report.tsv`, `redo.txt` (имена для `comfy_model_batch.py --redo`, следующий seed) и `listen.txt` (после `--max-tries` — на глаз).

```
python tools/pdm_model_check.py pdm-game
python tools/comfy_model_batch.py pdm-game ... --redo (Get-Content pdm-game\data\ai_models\redo.txt)
```

Подсказка модели: сети Pixal3D/TRELLIS.2 принимают только картинку, текст не читают. Текстом управляется шаг `refine` (Qwen-Image edit, `comfy_view_refine.py --prompt "..."`): он перерисовывает виды до генерации. Для плоского чёрного бархата в промпт добавляют материал и складки («black velvet sleeve with soft folds and visible shading»), иначе сеть не видит формы.
