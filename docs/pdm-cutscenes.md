# Ролики оригинала (RESOURCE/DESC/*.ani)

В оригинале нет списка роликов «по порядку». Ролик запускается событием, поэтому порядок — это порядок событий игры. Ниже — что найдено в скриптах и в коде DLL (выгрузка Ghidra, `ref/pdm-decomp`), структура `.ani` и какие ролики нигде не вызываются.

Путь к данным оригинала: `Корсары/RESOURCE/DESC/*.ani` (70 файлов). Формат `.ani` здесь — бинарная сцена, не текстовый `.ani` движка (см. [pdm-formats.md](pdm-formats.md)).

## Структура `.ani`: плейлист и лист

Разбор `Cinema.dll` (`FUN_10001910` — загрузка `Resource\Desc\<имя>[.ani]`, `FUN_10001af0` — шаг по записям `{type, time, size}`, `FUN_10001bb0` — обработчик записи) и всех 70 файлов показал два вида файлов.

- **Плейлист** — заголовок `(16, N, размер файла, 0)`, затем записи: маркер `(0x17, t, 0)` (12 байт) и сцена `(0x13, t, 0x58, имя[88])` (100 байт). Тип `0x13` — запуск дочерней сцены `Resource\Desc\<имя>.ani` (`FUN_10002680`, до 32 одновременно); `0x17` — остановка и освобождение предыдущих дочерних сцен перед очередной группой; тип `0` — первая сцена плейлиста (`FUN_10002310`), `8` — то же для другого пути. `t` — время старта группы (0, 10, 20, 30, 40); единица, вероятно секунды, не проверена.
- **Лист** — заголовок `(16, N, смещение_ключей, K)`, записи с именами ресурсов (`<имя>.cff`, `<имя>_a.cff`) и `K` ключей по 28 байт: 7 float (вектор, вектор, номер кадра) — предположительно камера (позиция и цель).

Плейлисты и их содержимое:

| Плейлист | Дочерние сцены (время) |
|---|---|
| `Intro`, `Intro_new` | Scene1, Scene2, Scene3 (0); Scene4, Scene5, Scene6 (10); Scene7 (20); Scene8, Scene10 (30); Scene12 (40) |
| `BuntR1` | Bunt (0), Hanging (10) |
| `BuntR2` | Black_marker (0), Bunt (0), Hanging (10) |
| `BeltropR1`, `R1` | Beltrop_punch (0), Hanging (10) |
| `Abordage_Eng` / `_Fra` / `_Spa` | `<Нац>_scene01` … `scene04` (0) |
| `Arest` | Arest1 (0), Arest2 (8) |
| `Hero_depart` | Hero_dep1, Hero_dep2 (0) |

Остальные файлы — листы: `Abordage_City_*`, `Beltrop_punch`, `Black_Marker`, `Bunt`, `CHERCH`, `Cherch_Sekret`, `Death`, `Death_Shark`, `end`, `Escape`, `Fight_*`, `FlagFort_*`, `FlagShip_*`, `Hanging`, `hero_v_pirate`, `Inauguracia_*`, `scene1`–`Scene12`, `Scene41`, `Underwater`, `vedma_fire`, `*_scene01–04`, `arest1/2`, `Hero_dep1/2`.

## Порядок в оригинале

- Новая игра: `MENU.dll` `FUN_100053d0`, пункт «Новая игра» (case 0): копирует `map.cpy` → `map.dat`, `mapparam.cpy` → `mapparam.ini`, шлёт `0xbc6` → `CORE.dll` `FUN_10004d40` запускает `intro` (Scene1…Scene12 по плейлисту выше). Shift нажат — заставка пропускается.
- Бунт: `BuntR1` (Bunt → Hanging).
- Абордаж: `Fight_*` / `Abordage_*` из ACTIONS, затем дуэль в каюте.
- Смерть: `death` / `death_shark` / `underwater` случайно.

## Ролики без найденного вызова

Плейлисты: `Arest`, `BeltropR1`, `R1`, `BuntR2`, `Hero_depart`, `Intro_new`, `Abordage_Fra`, `Abordage_Spa`.

Листы, не входящие ни в один плейлист и не вызываемые кодом: `Abordage_City_*`, `Escape`, `CHERCH`, `Cherch_Sekret`, `end`, `FlagFort_*`, `hero_v_pirate`, `Inauguracia_*`, `Scene9`, `Scene11`, `Scene41`, `vedma_fire`.

Языковые варианты (`_Eng`, `_Fra`, `_Spa`, `_Sp`) — версии разных языков; для ремастера нужен английский.

## Что не выяснено

- Обработчик `Engine_movie` в рантайме CORE и смысл поля персонажа `+0x1c4` в `0x7db`.
- Типы записей листа (3, 0xd, 0x1d …) и формат камеры/объектов — без этого сцену нельзя проиграть.
- Единицы времени `t` в плейлистах.
- Кто запускает `Arest`, `Hero_depart`, `BeltropR1`, `R1`, `BuntR2`, `Intro_new`.

## Что разобрано в сценах (лист `.ani`)

- Записи листа `{type, frame, size, payload}`: 0 модель (`.cff`, `_a.cff` — анимированные части), 1 FOV камеры (градусы), `0x1a` море и небо (296 байт погоды), `0xd` звук (имя[32], громкость), `0x11` конец, `4`/`0x1d` фейд (секунды, отрицательное — из чёрного). Огонь (6/0xb/0xc/0x1b), облака (0x14), взрыв (0x19), кровь (0x22) и фейды пока не воспроизводятся.
- Ключи камеры: по 28 байт, ключ i = кадр i, 15 кадров в секунду (66 мс).
- `_a.cff`: у всех частей одного объекта (NPC, судно) одинаковый трек ключей — это жёсткая группа. Конвертер (`tools/pdm_cutscene.py`) собирает группы в одну skinned-модель сцены `cinema_<сцена>.gm`: кость 0 — пустой корень, каждая группа — своя кость; `cinema_<сцена>.an` хранит позиции и кватернионы кадров всех костей (расширение формата `.an`, см. docs/ru/04), `.ani` — одно действие `play` на всю длину.
- Воспроизведение — `pdm-game/program/cutscene.c`: камера `FREE_CAMERA` в режиме `Scripted`, звуки по кадрам, `Cut_Next` по плейлисту; Space/Enter пропускают.
- Анимированные части (`_a.cff`) хранятся зеркально по x относительно неподвижных: конвертер зеркалит вершины, нормали, порядок вершин треугольников и ключи (x → −x, ry → −ry, rz → −rz). Без этого герой и женщина в сцене 3 стояли слева за кадром.
- Камера: ключи с угловым переходом через 2π интерполируются коротким путём, а скачок позиции между ключами (> 1 единицы или поворот > 0,5 рад) — склейка кадров: прежний кадр держится, промежуточные не рисуются. Время кадра ограничено 100 мс, чтобы загрузка сцены не съедала её начало.
- Погода: запись `0x1a` — см. раздел «Запись 0x1a». Текстуры оригинала закрыты, поэтому конвертер выбирает по имени неба одно из трёх свободных небес игры.

## Запись 0x1a (погода): раскладка

Разбор `CinemaSun.dll` (парсер `weather.ini`, методы через vtable `0x100070a8`; скрипт `ref/ghidra-scripts/DumpVtable.java`). Запись — 296 байт: 26 слов (104 байта), затем четыре имени по 48 байт (смещения 104 солнце, 152 луна, 200 небо, 248 море). Слово `idx` лежит по смещению `0xa8 + 4·idx` внутри структуры плагина, в записи — по `4·idx`. Цвет — слово `0x00RRGGBB` (в файле байты B, G, R, 0).

| idx | ключ weather.ini | | idx | ключ weather.ini |
|---|---|---|---|---|
| 0 | `angle` (в записи — высота солнца, рад) | | 13 | `sky_color` |
| 1 | `fog_color` | | 14 | `sky_tile` |
| 2 | `fog_max` | | 15 | `sky_specular` (в ролике служит цветом дымки) |
| 3 | `fog_density` | | 16 | `sky_bright_area` |
| 4 | `ambient` | | 17 | `sea_speed` |
| 5 | `ambient_spectrum` | | 18 | `sea_amplitude` |
| 6 | азимут солнца (в ini нет) | | 19 | `sea_frequency` |
| 7 | `direct_spectrum` (цвет солнца) | | 20 | `water_transparency` |
| 8 | `specular` | | 21 | `sea_tile` |
| 9 | `contrast` | | 22 | `sun_size` |
| 10 | `sky_speed` | | 23 | `moon_size` |
| 11 | `sky_fog_near` | | 24 | `moon_angle` |
| 12 | `sky_fog_far` | | 25 | `flags` |

- Солнце: направление `x = sin(az)·cos(el)`, `y = sin(el)`, `z = cos(az)·cos(el)`, радиус позиции 1000. `sun_size < 0` — вместо солнца рисуется луна размером `−sun_size`; `sun_size == 0` — предустановка 9-го периода.
- Объект `coordinator` — свет для моделей (карта 256×256); `sky`/`sea` — текстуры; параметры моря (`speed`, `amplitude`, `tile`, `transparency`, `frequency`) уходят сообщением в модуль моря. Какой слот `coordinator` чему соответствует — не подтверждено.
## Море оригинала: волны и физика воды (`sea.dll`)

Разбор настоящего класса моря `sea.dll` (vtable `0x1000a0cc`, `ref/pdm-decomp/sea.dll.vt.c`; два меньших класса `sea.dll`/`nsea.dll` по vtable `0x1000a0a0`/`0x1000a098` — вспомогательные).

- Сообщение `0xe` от `CinemaSun`/`SUN` (slot 15, `FUN_10003040`), формат `ffff_ll_fff_f`: `+0x10` скорость волн (`sea_speed`), `+0x14` амплитуда (`sea_amplitude`), `+0x18` тайл (`sea_tile`), `+0x1c` прозрачность воды (`water_transparency`), `+0x20` частота (`sea_frequency`, int; при смене пересчитывается таблица), `+0x24` id модели («model»: карта острова/берега), `+0x28..0x30` вектор солнца ×50, `+0x34` float. Те же три float (скорость, амплитуда, прозрачность) море раз в кадр читает из слотов 6, 7, 8 объекта `coordinator`, куда их кладёт `CinemaSun`.
- Умолчания при создании: скорость 0,0012, амплитуда 0,0005, тайл 1,0, прозрачность 1024, частота 64.
- Высота волны (slot 20, `FUN_10002f60`, `GetHeight(x, z)`): сумма трёх октав по таблице из 1024 значений синуса, `h = (Σ…) · amplitude · K + level`, где `K = 125 / max|Σ|` — таблица нормируется (`FUN_10002..` в конце инициализации, `_DAT_1000cba0 = 125 / |Σ|`). Значит пик волны ≈ `125 · amplitude`: амплитуда ролика 0,0002–0,0006 даёт 0,025–0,075 единицы, а не 3 м, как у `Sea.Sea2.Amp1` игры. Конвертер задаёт `.amp = sea_amplitude · 125`.
- `level` лежит в `+0x144` объекта моря и задаётся slot 19 (`FUN_100010d0`: шесть float в `+0x140..+0x154`); `+0x140 = level / amplitude`. Уровень моря, как и рамка, приходит не из записи ролика, а от того, кто вызвал slot 19 (остров/модель), — поэтому в записи его нет, а lift подбирается по кадрам.
- Физики воды (плавучесть, качка кораблей) в сцене нет: корабли в роликах двигаются ключами камеры/моделей. Водная поверхность рисуется сеткой по высотам `GetHeight` с цветом по прозрачности и туману.
- Шейдера у оригинала нет: модуль 2000 года, фиксированный конвейер DirectX (в `sea.dll` нет ни строк шейдеров, ни технических имён, в отличие от нашего `sea` движка с техниками). Вид воды в игре — наш рендер, не оригинальный.

## Время суток и погода в роликах

Отдельного «времени суток» в роликах нет, оно задаётся тремя способами (проверено по всем 70 `.ani`):

- **Запись `0x1a`** (все сцены интро, `Bunt`, `Hanging`, `Death_Shark`, `Underwater`, `arest*`, `Hero_dep*`, `end`, `Escape`, `Black_Marker`): один «период» погоды целиком — высота солнца `el` (рад), азимут `az`, цвета, туман, море, небо. Времени и интерполяции нет: кадр 0, одно состояние на весь ролик. Высота солнца: `Scene12` и `Black_Marker` 1,57 (в зените), `Death_Shark` 1,47, `Scene2`/`Scene4`/`Scene7` 0,79–0,85 (день), `Scene3` 0,62, `scene1` 0,50, `Hanging` 0,49, `Scene10` 0,25, `Scene8` 0,15 (низко, интерьер), `Scene5` 0,10 (закат у горизонта), `Scene6` 0 с `sun_size = 0` (предустановка).
- **Флаг `flags` (слово 25)** = 1 у `Hanging` и `Scene10` — ночь; в этих же записях `sun_size < 0` (−143,6 и −162,3), то есть рисуется луна размером 143,6 / 162,3. У остальных `flags = 0`, `sun_size` 100 (`Escape` 430).
- **Запись `0x7` — час суток (float)**, у роликов без `0x1a`: `Abordage_City_*`, `Beltrop_punch`, `FlagShip_*`, `Inauguracia_*`, `Scene9`, `Scene11`, `Scene41`, `hero_v_pirate` — 12,0 (полдень); `CHERCH` — 5,0; `Cherch_Sekret` — 2,0; `vedma_fire` — 0,0. Такой ролик берёт солнце, небо и море по этому часу из `weather.ini` (периоды `angle`, см. выше).
- **Запись `0x20`** (без данных) — час берётся из игровых часов: `Death`, `Fight_*`, `FlagFort_*`, `FlagShip_*`, `*_scene01–04`.

Как это применять в ремастере: интро и ролики с `0x1a` — брать значения из записи (так и делает конвертер, ночь — `flags`/`sea_night`); ролики с `0x7` — час по таблице периодов `weather.ini` игры; ролики с `0x20` — текущее время игры.

## Как устроена погода в оригинале (`RESOURCE/weather.ini`)

- Файл `weather.ini` (590 строк) — 19 «периодов» `__THE__NEXT__TIME__PERIOD__ N`, 31 ключ в каждом. `angle h,f` — время периода (час и доля: `0,5.5` — 5:30). Периоды идут по кругу суток: 0 — 0:00 … 18 — 23:00. Игровой модуль `SUN.dll` по времени выбирает соседние периоды, ролик (`CinemaSun.dll`) — один период, лежащий прямо в записи `0x1a` (те же 26 слов, без `angle`: в записи в слове 0 стоит высота солнца в радианах). Линейная интерполяция между периодами — предположение, по коду не подтверждена.
- Ключи: `fog_color`, `fog_max`, `fog_density`, `ambient` (интенсивность), `ambient_spectrum`, `direct_spectrum` (цвет солнца), `specular`, `contrast`, `sky_*`, `sea_*`, `sun_size`, `moon_size`, `moon_angle`, `flags` (1 — ночь), `texture_sun/moon/sky/sea`, `wind_speed`.
- Периоды (час → небо / море / море-амплитуда): 0:00, 1:00 ночь (`sky_night_star`/`sky_cloud`, `sea_night`, амплитуда 0,00006, `flags 1`); 3:00 рассвет-дымка (`sky_mor`/`sea_mor`, туман 0,5); 5:00–5:30 утро (`sky_mor`/`sky_morn`, 0,00019–0,00029); 7:00 `sky_d`; 9:00–13:00 день (`Sky_day`, `Skay_day1`, `sky_overcast` в 12:00 с `sun_size 200`, `S_2_clouday`, `sea_day`, 0,0002–0,00032, туман 0,999); 14:30–15:00 шторм (`sky_r`/`sea_r1`, туман серый 75/55, амплитуда 0,0007–0,0011, ветер 1,6–2,2, `sun_size 16000`); 16:00 `sky_d`; 17:00 закат (`direct 255,100,80`); 17:30–19:00 `Sky_Zak3`/`sea_z1_`/`sea_morn`; 20:00 `direct 255,120,90`; 23:00 ночь (`fog 0,50,100`, `flags 1`).
- Роликам нужны только эти же слова, поэтому конвертер переносит их в сцены: цвет солнца (`direct_spectrum`), ambient = `ambient_spectrum × ambient`, цвет дымки, высота/азимут, амплитуда `×125`, имя неба → один из свободных пресетов игры (оригинальные `*.tf` закрыты). Туман (`fog_density`, `fog_max`, `sky_fog_near/far`) оригинала в игру не переносится: его единицы не выяснены, `sky_fog_near/far` в интро нулевые.
- Что перенесено, а что нет — таблица: цвета солнца/ambient/дымки, высота и азимут, амплитуда моря — перенесены; тайл, частота и прозрачность моря, `contrast`, `specular`, плотность тумана, луна (`moon_size`, `sun_size < 0`) — нет (в игре у них иной смысл или нет аналога).

## Типы записей листа

Записи с кадром 0 исполняются при загрузке листа. Время обработчика — dt в мс; тип 5 добавляет 66 мс (один кадр).

| тип | значение |
|---|---|
| 0 | модель `.cff` / `_a.cff` |
| 1 | поле зрения камеры (градусы) |
| 2, 3 | ключи / вспомогательные данные камеры |
| 4, 0x1d | фейд (секунды; отрицательное — из чёрного) |
| 5 | пауза на один кадр |
| 6 | огонь |
| 7 | час суток (float) |
| 0xa–0xc, 0x1b | огонь ночью |
| 0xd, 0xe | звук (имя[32], громкость), высота солнца |
| 0x11 | конец |
| 0x14 | дым пушек |
| 0x19 | взрыв |
| 0x1a | погода (см. выше) |
| 0x1c, 0x1f | не разобраны |
| 0x1e | binokular — чёрные полосы сверху и снизу |
| 0x20 | час из игровых часов |
| 0x21 | параметры моря (68 байт) |
| 0x22 | кровь |
| 0x23, 0x25, 0x26 | не разобраны |

## Применение в игре

- Погода (`cutscene.c`): по имени неба один из трёх свободных пресетов (`overcast`/`cloud` → `storm`, `sky_r`/`sky_d` → `sunset`, остальное → `day`); `sea_night` при небе не `overcast` → ночь. Из записи берутся цвет прямого света (idx 7), ambient (idx 5), цвет дымки (idx 15, иначе idx 13), высота и азимут солнца, амплитуда моря (idx 18, ×125); `.lift` — подъём над нулём моря.
- Луна (`sun_size < 0`): значение `.moon` записывается, в игре пока не рисуется.

## Не выяснено

- Отрицательные «типы» (−0x28 в `Scene10`, −0x1e в `Scene7`, −0x14 в `Scene6`, −0xa в четырёх файлах).
- Соответствие слотов `coordinator` и текстур `sky`/`sea` слотам записи.
- Смысл float6/int6 записи, типы `0x1c`, `0x1f`, `0x23`, `0x25`, `0x26`.
- Текстуры неба, солнца и луны оригинала закрыты — заменяются свободными.
- Уровень моря в мире ролика.

## Луна ночных роликов

- Ночью (`flags` = 1: Hanging, Scene10) `cutscene.c` создаёт `SunGlow` в режиме луны; текстура `weather\moon.tga.tx` генерируется `tools/make_moon.py` (аддитивное смешение: вне диска цвет чёрный).
- Движок рисовал солнце и луну только для неба из нескольких слоёв (`SKY::Realize`, ветка `aSkyDirArray.size() > 1`); добавлена отрисовка и для одного слоя.
- После смены высоты и азимута нужно `Weather.isDone = ""`, иначе `whv_sun_pos` остаётся от `Sea_CreateWorld`.
- Азимут записи отсчитывается от направления взгляда ролика, у движка — от оси x, поэтому ночью берётся `azimuth − π/2`.

## Эффекты роликов: что нашли в дизассемблере Cinema.dll

- Запись .ani = `{type:int, frame:int, size:int, payload}`; `Cinema.dll` (функция 0x10003150, таблица переходов 0x10003df0) исполняет их по кадру.
- Тип 13 — звук (в Scene7 `boom.wav` на кадре 360), тип 20 — сущность `canclouds` (CANCLOUDS.dll: выстрел и дым орудия; payload 6 float: x,y,z и углы), тип 25 — `explosion_x` (EXPLOSION_X.dll: попадание; payload x,y,z).
- Координаты — в тех же единицах, что ключи камеры (×K=2.3 и + lift сцены у нас). Выстрелы стоят на борту дальнего корабля вдоль ряда портов (z≈5, шаг по x ≈0.3 за 3–6 кадров), попадания — на носу/планшире ближнего (кадры 374 и 390).
- CANCLOUDS (smoke.tf): до 20 спрайтов, эмиссия каждые 100 мс, направление `(sin a2·cos a1, −sin a1, cos a2·cos a1)`, скорость 4+4.5·rand, затухание скорости, жизнь ≈8 с — в оригинале дым выстрела «висит» у борта.
- EXPLOSION_X: 64 куска (модели particle0..4), гравитация 0.5, у половины шлейф из спрайтов fire.tf, исчезают под водой со всплеском.
- Конвертер: `tools/pdm_cutscene.py` пишет `.fx.fN` (frame/kind/x/y/z), `cutscene.c: Cut_Effects` создаёт системы `gunflash`/`shothit` (`tools/make_cannon_fx.py`) в этих точках. Размеры систем масштабируются: дальний борт ≈13 ед. от камеры, поэтому клубы ~0.5 ед., иначе их не видно; обломки у ближнего корабля (≈2 ед.) должны быть мелкими.
- Движение: волна под корпусами и камерой проходит двухступенчатый фильтр (≈2 с на ступень), чтобы корабль не дёргало от мелкой ряби.

## Настройка сцен: словари конвертера и поля сцены

- Флаги (запись 6: x y z размер yaw + текстура) делаются тканью `tools/pdm_cutscene.py: cloths`. Флаги дальних кораблей и флаги корабля, который идёт в ролике (ближайшая движущаяся группа ближе `RIDE_GAP`, путь больше `RIDE_TRAVEL`), привязаны к костям группы и мельче (`FAR_FLAG_SCALE`, `RIDE_FLAG_SCALE` = 0,3): неподвижная ткань отстала бы от корабля (Scene7).
- Дальние корабли (дальше 150 ед.) — отдельная far-модель в своём начале: движок не рисует кости, ушедшие на сотни единиц от коробки остальных.
- `SKIES` — небо сцены (`clear`, `haze`, `storm`), `WEATHER_OF` — взять погоду из другой сцены, если в листе нет записи 0x1a (Scene6 ← Scene12, Scene11/41/9 ← Scene4). `SUN_TURNS` — поворот солнца; `SUN_DIM` — множитель цвета солнца (стена каюты Scene8 ярче оригинала).
- `DRAFTS` — осадка/высота комнаты над водой (`Cut_Ride` каждый кадр переставляет модели на волну + `draft`, `lift` на это не влияет). `TILTS` (`.tilt`) — наклон комнаты вокруг оси вида: единственный способ сдвинуть линию моря в окне (горизонт на уровне глаз камеры); наклон опускает часть комнаты, поэтому `DRAFTS` поднимают (Scene8: tilt 0,05, draft 1,0).
- `NIGHT_DARK` (`.dark`) — доля света, оставшаяся ночью (Scene10 = 0,35).
- Обзор в подзорную трубу (запись 0x1e `binokular`): fader с текстурой `cinema/binocular.tga.tx` (`tools/make_binocular.py`, мягкая круглая виньетка + полосы), техника Fader в `maineffects.fx` с альфой texture×diffuse. Скрипт нужно запускать вручную: `python3 tools/make_binocular.py pdm-game/resource`.
- Туман (`Weather.Fog`) на модели кораблей не действует: «дымка» Scene7 держится на цвете неба/моря, корабль остаётся чётче оригинала.
- Не решено: чёрные кубы вместо обломков (`particles_inv` в system.log), цвет карты Scene12, letterbox-полосы оригинала.

## Почему перенос роликов оказался таким сложным

Ролик оригинала — не видео, а сценарий, который исполняет `Cinema.dll` поверх живого мира: камера, модели, море и погода пересчитываются каждый кадр. Просто проиграть его на другом движке нельзя, каждую сцену пришлось собирать заново из частей.

1. **Закрытый формат и нет исходников.** `.ani` — таблица записей `{тип, кадр, размер, данные}`; смысл типов (20 — дым пушек, 25 — взрыв, 0x1a — погода, 0x1e — подзорная труба) выяснялся дизассемблером `Cinema.dll`, `sea.dll`, `CANCLOUDS.dll`, `EXPLOSION_X.dll`. Часть полей записи 0x1a до сих пор не расшифрована.
2. **Номера ≠ порядок.** Плейлист, сцены и планы видео не совпадают (shot12 = каюта + начало сцены 7 и т. д.), куски одной сцены склеиваются из нескольких `.ani`; эталон приходилось резать на планы и сверять кадр за кадром.
3. **Единицы и системы координат.** Ключи камеры и моделей — в «малых» единицах (×K = 2,3), корабли дальше 150 ед. движок не рисует (отдельная far-модель), анимированные группы отзеркалены по x, азимут солнца отсчитывается от другой оси.
4. **Море живёт по своим правилам.** Оригинал ставит корабли на волну (`Cut_Ride`), а камеру — над самой высокой волной; линия горизонта всегда на уровне глаз, поэтому «опустить море» значит наклонить комнату (`tilt`), а наклон топит пол — отсюда подбор `draft` на каждую сцену. Общей настройки нет: каждая сцена дописывалась отдельно.
5. **Погода сцены — не пресет, а 26 чисел + 4 текстуры** закрытых ассетов (небо, солнце, луна, море). Их заменяли свободными (`make_haze_sky.py`, `make_clear_sky.py`, `make_moon.py`), а цвета подбирали по кадрам оригинала; у части сцен записи погоды нет вообще (`WEATHER_OF`).
6. **Эффекты написаны в DLL, а не в данных.** Выстрелы и взрывы — код `CANCLOUDS`/`EXPLOSION_X` со своими текстурами `.tf`; пришлось повторить их частицами (`make_cannon_fx.py`, `pdm_effects.py`) и подгонять размеры под расстояние до камеры.
7. **Ограничения движка.** Туман не действует на модели, у камеры не было скриптового режима (добавлен `Scripted` в `free_camera.cpp`), видео — только через DirectShow (на Linux добавлен FFmpeg), нужна техника Fader с альфой для виньетки подзорной трубы, у небо-одного-слоя не рисовались солнце и луна.
8. **Нельзя проверить глазами сразу.** Сцена идёт десятки секунд, дефекты (прыжки модели, флаги, отставшие от корабля) видны только в записи; поэтому процесс — запись одной сцены → коллаж с оригиналом → замечания (скилл `compare-frames`, `edit-cutscene`).
9. **Лицензия.** Оригинальные ассеты и закрытые утилиты в репозиторий не попадают: всё конвертируется из установленной игры генераторами (`pdm_cutscene.py`, `pdm_effects.py`), поэтому каждое исправление — это правка конвертера и перегенерация, а не данных.
